# Contributing to Awesome 3D AI, SEO & GEO for 3D Web

Thank you for your interest in contributing! 🎉

This repository is a community-driven collection of resources for developers building modern 3D websites, WebGL applications, Three.js projects, React Three Fiber applications, and AI-powered 3D experiences.

Contributions are welcome and appreciated.

---

## How You Can Contribute

There are many ways to improve this repository:

* Add useful AI tools for 3D development
* Add 3D modeling and development resources
* Add Three.js, React Three Fiber, WebGL, or WebGPU resources
* Add SEO resources relevant to 3D websites
* Add GEO and AEO resources
* Add AI search resources
* Add performance and optimization tools
* Add structured data and schema resources
* Add useful tutorials and guides
* Improve existing descriptions
* Fix broken or outdated links
* Remove resources that are no longer maintained
* Correct inaccurate information
* Improve the organization of categories
* Improve documentation and examples

---

## Before You Contribute

Please make sure your contribution:

* Is relevant to the 3D Web, AI, SEO, GEO, AEO, or related developer ecosystem.
* Provides genuine value to developers.
* Is not simply promotional content.
* Does not duplicate an existing entry.
* Uses accurate and concise descriptions.
* Links to a legitimate and working resource.
* Preferably links to official documentation or the original project.
* Follows the existing structure and formatting of the repository.

---

## Adding a New Resource

When adding a new resource, place it in the most appropriate category.

A good resource entry should be:

```text
- [Resource Name](https://example.com) — Short description explaining what it does and why it is useful.
```

Keep descriptions concise and factual.

### Good Example

```text
- [Three.js](https://threejs.org/) — JavaScript 3D library for creating interactive 3D experiences on the web.
```

### Avoid

```text
- [Amazing 3D Tool](https://example.com) — The world's best and most powerful 3D tool that everyone should use!
```

Avoid exaggerated claims, unnecessary marketing language, and keyword stuffing.

---

## Prefer Official Sources

Whenever possible, link directly to the official project, documentation, or organization.

For example:

```text
Preferred:
https://threejs.org/

Avoid when possible:
https://some-third-party-site.example/threejs-guide
```

Third-party tutorials can still be valuable when they provide unique and useful information.

---

## Resource Quality

Before submitting a resource, consider:

* Is it actively maintained?
* Is the website or repository accessible?
* Is the information accurate?
* Is the resource relevant?
* Does it provide meaningful value?
* Is the description clear?
* Is the link correct?
* Does it already exist somewhere in the repository?

For tools and software projects, check the project's current status before adding it.

---

## Broken or Outdated Resources

If you find a broken, outdated, or abandoned resource, you can:

1. Open an Issue describing the problem.
2. Submit a Pull Request removing or updating it.
3. Suggest a maintained alternative.

When replacing a resource, explain why the replacement is more useful or better maintained.

---

## Pull Requests

Before opening a Pull Request:

1. Fork the repository.
2. Create a new branch.
3. Make your changes.
4. Check the Markdown formatting.
5. Verify all added links.
6. Review your changes.
7. Commit your changes.
8. Open a Pull Request.

Example:

```bash
git clone https://github.com/GLBKit/awesome-3d-ai-seo-geo.git

cd awesome-3d-ai-seo-geo

git checkout -b add-new-resource
```

After making your changes:

```bash
git add .

git commit -m "Add new 3D resource"

git push origin add-new-resource
```

Then open a Pull Request on GitHub.

---

## Pull Request Guidelines

Please keep Pull Requests focused.

A good Pull Request should:

* Have a clear title.
* Explain what was changed.
* Explain why the change is useful.
* Keep unrelated changes out of the PR.
* Follow the repository's existing Markdown style.
* Include working links.
* Avoid unnecessary formatting changes.

For larger changes, consider opening an Issue first to discuss the idea.

---

## Commit Messages

Use clear and descriptive commit messages.

Good examples:

```text
Add WebGPU resources

Fix broken Three.js documentation link

Update SEO tools section

Remove outdated AI tool

Improve GEO resources
```

Avoid vague messages such as:

```text
update

changes

fix stuff

misc
```

* 3D optimization

## Style Guidelines

Please keep contributions:

**Clear**

Use simple language that developers can understand quickly.

**Concise**

Avoid unnecessary explanations in resource descriptions.

**Factual**

Describe what a resource actually provides.

**Neutral**

Avoid promotional language and unsupported claims.

**Consistent**

Follow the formatting and organization already used in the repository.

---

## Markdown Guidelines

Use standard GitHub-flavored Markdown.

For resource lists:

```markdown
- [Resource Name](https://example.com) — Description.
```

For categories:

```markdown
## Category Name
```

Keep formatting consistent with the rest of the README.
